# 性能定位指南RAG系统需求文档

## 一、项目概述

### 1.1 项目背景

昇腾AI计算平台开发者在使用MindStudio进行模型训练和推理时，常遇到性能问题（如训练速度慢、通信延迟大、算子性能低下等）。现有文档资料分散在昇腾社区网站，开发者难以快速找到针对性的解决方案。

本项目旨在构建一个基于RAG（Retrieval-Augmented Generation）技术的智能问答系统，帮助开发者快速定位和解决性能问题。

### 1.2 项目目标

构建一个能够：
- 理解开发者性能问题描述
- 精准检索相关技术文档
- 生成专业、准确的解决方案
- 提供操作指导和工具使用说明

的智能问答系统。

### 1.3 目标用户

| 用户类型 | 特征 | 主要需求 |
|----------|------|----------|
| 初学者 | 刚接触昇腾平台 | 整体流程指导、概念解释 |
| 开发者 | 正在进行模型训练/推理 | 具体问题定位、工具使用 |
| 性能工程师 | 负责性能优化 | 高级调优方法、案例分析 |
| 专家用户 | 熟悉平台，需要快速查找 | 精准检索、快速定位 |

## 二、功能需求

### 2.1 核心功能

#### F1. 智能问答

**功能描述**：用户输入性能相关问题，系统返回专业的解决方案。

**输入**：用户自然语言问题
**输出**：结构化的解决方案，包含：
- 问题诊断结果
- 定位步骤
- 工具使用指导
- 相关文档引用

**用户场景**：

| 场景类型 | 用户问题示例 | 期望回答 |
|----------|--------------|----------|
| 定位指导 | "模型训练很慢，怎么定位问题？" | 给出整体定位流程，推荐工具 |
| 问题诊断 | "通信时间波动大是什么原因？" | 解释快慢卡问题，给出定位方法 |
| 工具使用 | "msprof-analyze怎么用？" | 工具介绍、命令示例、结果解读 |
| 概念理解 | "什么是Host Bound问题？" | 概念定义、影响说明、解决方法 |
| 操作步骤 | "MindStudio Insight如何查看通信耗时？" | 具体操作步骤、截图说明 |

#### F2. 文档检索

**功能描述**：根据用户问题，从知识库中检索相关文档片段。

**要求**：
- 检索准确率 > 90%
- 检索召回率 > 85%
- 支持模糊匹配和语义匹配
- 返回结果包含文档来源信息

#### F3. 多轮对话（可选-Phase 3）

**功能描述**：支持用户追问和深入讨论。

**要求**：
- 保存对话上下文
- 支持追问细节
- 支持话题切换

#### F4. 图片引用（可选-Phase 2）

**功能描述**：在回答中引用文档中的相关图片。

**要求**：
- 提取图片标题和描述
- 在回答中标注图片来源
- 可选：展示图片内容

#### F5. 链接导航

**功能描述**：提供相关文档的链接，方便用户深入阅读。

**要求**：
- 显示文档标题和来源URL
- 支持父子主题关系导航
- 支持相关文档推荐

### 2.2 辅助功能

#### F6. 问题分类

**功能描述**：自动识别用户问题的类型（定位指导、工具使用、概念理解等）。

**用途**：优化检索策略和回答模板选择。

#### F7. 关键词提取

**功能描述**：从用户问题中提取关键术语（如"通信"、"快慢卡"、"msprof"）。

**用途**：增强关键词检索效果。

#### F8. 用户反馈收集（可选-Phase 4）

**功能描述**：收集用户对回答的评价。

**要求**：
- 支持点赞/点踩
- 支持文字反馈
- 用于系统持续优化

## 三、技术需求

### 3.1 文档预处理

#### T1. 文档切分

**需求描述**：将原始文档切分成适合检索的chunks。

**切分策略**：
- 采用按章节切分（方案三）+ 混合切分（方案六）
- 按 `####` 标题切分成独立chunks
- 过长章节（>2000字符）进行二次切分
- 过短文档（<1500字符）保持完整

**Chunk内容要求**：
- 包含章节标题
- 包含正文内容
- 包含图片描述（如"图1 概览界面"）
- 包含元数据（文档标题、父主题、来源URL）

#### T2. 元数据提取

**需求描述**：从文档中提取结构化元数据。

**提取内容**：
- 文档标题
- 父主题关系
- 章节标题
- 图片标题列表
- 跨文档链接
- 关键术语

#### T3. 文本清洗

**需求描述**：清理文档中的噪声内容。

**清洗内容**：
- 移除HTML残留标签
- 统一格式（标题、列表、段落）
- 处理特殊字符
- 规范化空白字符

### 3.2 向量化与索引

#### T4. Embedding模型

**需求描述**：选择合适的文本向量化模型。

**选型要求**：
- 支持中文
- 效果稳定
- 可本地部署（优先）

**推荐方案**：
- Phase 1: bge-large-zh（本地部署）
- Phase 4: 可切换为OpenAI embeddings（生产环境）

#### T5. 向量数据库

**需求描述**：存储和检索向量化的文档chunks。

**选型要求**：
- 支持本地部署
- 支持元数据过滤
- 支持混合检索

**推荐方案**：
- Phase 1-2: Chroma（快速验证）
- Phase 3-4: Milvus（生产环境）

#### T6. 索引构建

**需求描述**：构建高效的检索索引。

**索引类型**：
- 向量索引（用于语义检索）
- 关键词索引（用于精确匹配）
- 元数据索引（用于过滤）

### 3.3 检索系统

#### T7. 混合检索

**需求描述**：结合向量检索和关键词检索。

**检索策略**：
- 向量检索：语义相似度匹配
- 关键词检索：BM25算法
- 混合融合：加权组合两种结果

**参数要求**：
- 向量检索权重：0.6-0.7
- 关键词检索权重：0.3-0.4
- 可根据问题类型动态调整

#### T8. 知识图谱增强

**需求描述**：利用文档结构关系增强检索。

**利用信息**：
- 父子主题关系：检索时扩展父文档内容
- 跨文档链接：检索相关文档
- 概念关系：关联相似概念

#### T9. 重排序

**需求描述**：对检索结果进行相关性排序。

**排序因素**：
- 语义相似度得分
- 关键词匹配度
- 文档权威性（是否是核心文档）
- 章节完整性

### 3.4 生成系统

#### T10. LLM选择

**需求描述**：选择合适的语言模型生成回答。

**选型要求**：
- 支持中文
- 理解能力强
- 支持长文本输入

**推荐方案**：
- Phase 1-2: GPT-4 / Claude（开发验证）
- Phase 3-4: DeepSeek / 本地模型（降低成本）

#### T11. Prompt模板设计

**需求描述**：设计专业的回答生成模板。

**模板要求**：
- 针对不同问题类型设计不同模板
- 包含系统角色定义（性能优化专家）
- 包含回答格式要求
- 包含引用规范

**模板类型**：

| 问题类型 | 模板特点 |
|----------|----------|
| 定位指导 | 流程化回答，步骤清晰 |
| 问题诊断 | 先解释原因，再给出方法 |
| 工具使用 | 命令示例 + 参数说明 |
| 概念理解 | 定义 + 影响 + 解决方法 |

#### T12. 上下文构建

**需求描述**：构建LLM输入的上下文。

**上下文内容**：
- 用户问题
- 检索到的chunks（按相关性排序）
- 图片描述（可选）
- 相关文档链接

**长度限制**：
- 总上下文不超过模型限制（如4000 tokens）
- 优先保留高相关性chunks

### 3.5 系统集成

#### T13. API接口

**需求描述**：提供系统访问接口。

**接口类型**：
- REST API：问答接口
- WebSocket：多轮对话（可选）

**接口要求**：
- 输入：用户问题 + 可选参数
- 输出：回答内容 + 来源文档 + 相关链接
- 响应时间 < 3秒

#### T14. 前端界面（可选）

**需求描述**：提供用户交互界面。

**界面要求**：
- 问题输入框
- 回答展示区
- 文档来源展示
- 反馈按钮

| 阶段 | 内容 | 时间 | 交付物 |

| **Phase 1** | 文档预处理 + 基础检索 + 简单回答 | 1-2周 | MVP系统 |

| 任务 | 描述 | 优先级 |

### 7.3 技术栈选型

#### Phase 1-2（开发验证）

```
文档预处理：Python脚本
Embedding：bge-large-zh（本地）
向量库：Chroma（本地）
LLM：GPT-4 API / Claude API
框架：LangChain / LlamaIndex
```

#### Phase 3-4（生产环境）

```

Embedding：bge-large-zh / OpenAI
向量库：Milvus（分布式）
LLM：Claude / DeepSeek
框架：自研（更灵活）
监控：检索日志 + 用户反馈
```

## 八、关键决策点

### 8.1 已确定决策

| 决策点 | 决策结果 | 原因 |
|--------|----------|------|
| 切分方案 | 按章节切分 + 混合切分 | 文档有明确结构，适合按标题切分 |
| Embedding模型 | bge-large-zh | 中文效果好，可本地部署，免费 |
| 向量库 | Chroma（先）→ Milvus（后） | 先快速验证，后生产部署 |
| 检索策略 | 混合检索 + 知识图谱增强 | 平衡精度和召回率 |

### 8.2 待确定决策

| 决策点 | 选项 | 需要进一步讨论 |
|--------|------|----------------|
| 多轮对话 | 是否需要？何时实现？ | Phase 3 可选功能 |
| 图片展示 | 是否在回答中展示图片？ | Phase 2 可选功能 |
| 代码执行 | 是否支持命令生成/执行？ | 暂不实现，后续考虑 |
| 版本管理 | 是否支持文档版本切换？ | 暂不实现，后续考虑 |
| 用户反馈 | 是否收集用户评价？ | Phase 4 可选功能 |
| 本地LLM | 是否使用本地模型？ | 根据成本和隐私需求决定 |

## 九、风险与应对

### 9.1 技术风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 检索效果不佳 | 回答质量下降 | 多种检索策略对比，迭代优化 |
| LLM回答不准确 | 用户满意度下降 | Prompt优化，添加回答校验 |
| 文档更新滞后 | 信息过时 | 建立定期更新机制 |

### 9.2 数据风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 文档覆盖不全 | 无法回答某些问题 | 收集更多文档，标注知识边界 |
| 图片信息丢失 | 回答缺少视觉辅助 | 提取图片描述，可选展示图片 |
